# レトロ修復工房（仮） — retro-restoration-game

古いラジオ・時計・カメラを、指でこすって磨いて部品をはめて直す、スマートフォンのブラウザで遊べる2Dゲームです。
将来のiOS・Android化と収益化を見すえた、**市場検証用のMVP**です。

- 1ステージ 約1〜3分
- 説明を読まずに遊べる操作（なぞる・往復させる・ドラッグ・タップ）
- 制限時間なし／失敗してもペナルティなし
- **圏外（WiFiなし）でも遊べる**（一度開けば端末に保存される）
- 広告・課金・ガチャ・ログインボーナスは入れていません

---

## 1. 起動手順（Windows PowerShell）

Node.js 18以上が必要です（開発時の確認環境：Node v24.21.0 / npm 11.19.0）。

```powershell
cd C:\DevFolder\retro-restoration-game
npm install
npm run dev
```

表示された `http://localhost:5173/` をブラウザで開きます。
（5173が他のプロジェクトで使われているときは `npm run dev -- --port 5291` のように別の番号を指定してください。）

### 家のWiFiで、スマホ実機から開く

PCとスマホを**同じWi-Fi**につないでから、PowerShellで:

```powershell
cd C:\DevFolder\retro-restoration-game
npm run dev -- --host
```

PowerShellに出る `Network: http://192.168.x.x:5173/` を、スマホのブラウザで開きます。
（表示されない場合は `ipconfig` でPCのIPv4アドレスを調べ、`http://<そのIP>:5173/` を開いてください。
Windowsファイアウォールの確認が出たら「プライベートネットワーク」を許可します。）

**注意**：この方法（`npm run dev`）では圏外対応は働きません。PCの電源を切ると遊べなくなります。
外に持ち出して遊ぶには、次の第2節のやり方で公開してください。

### 本番ビルドと確認

```powershell
cd C:\DevFolder\retro-restoration-game
npm run build
npm run preview
```

`npm run build` は「型チェック → ビルド → 圏外対応の仕上げ（`scripts/postbuild.mjs`）」を順に実行します。

### テスト

```powershell
cd C:\DevFolder\retro-restoration-game
npm test
```

## 2. 圏外（WiFiなし・PCなし）で遊べるようにする

このゲームは **PWA** にしてあります。
電波のある所で**一度だけ**開けば、ゲーム一式がスマホの中に保存され、そのあとは機内モードでも遊べます。

### 手順（家で1回だけ・PCが必要）

**① 無料のホスティングに置く**

いちばん手数が少ないのは Netlify Drop です。アプリのインストールは不要です。

```powershell
cd C:\DevFolder\retro-restoration-game
npm run build
explorer .
```

開いたフォルダの中の `dist` を、ブラウザで開いた <https://app.netlify.com/drop> の枠にドラッグするだけです。
`https://○○○.netlify.app` のようなURLが出ます。

Cloudflare Pages を使う場合（アカウントとブラウザでのログインが必要）:

```powershell
cd C:\DevFolder\retro-restoration-game
npm run build
npx wrangler pages deploy dist --project-name retro-restoration-game
```

> **必ず `https://` のURLで開いてください。** 圏外対応（Service Worker）は、安全な接続（HTTPS）か `localhost` でしか働きません。
> `http://192.168.x.x:5173/` では保存されません。

**② スマホでそのURLを1回開く**

タイトル画面の下に **「✓ 保存ずみ：電波がなくても遊べます」** と出れば完了です。

**③ ホーム画面に置く（おすすめ）**

- iPhone（Safari）：共有ボタン → 「ホーム画面に追加」
- Android（Chrome）：右上の「︙」→ 「アプリをインストール」または「ホーム画面に追加」

アイコンはゲームのラジオの絵です。ブラウザの枠が消えて、アプリのように全画面で開きます。
これで**圏外でも、PCがなくても**、アイコンから起動して遊べます。

### 更新の受け取り方

私がゲームを直して再デプロイしたあと、**電波のある所でゲームを1回開けば**新しい版に入れ替わります。
圏外のままなら、前に保存した版がそのまま動きます（遊べなくなることはありません）。

### 仕組み（技術メモ）

- `public/sw.js` が Service Worker。ビルド後に `scripts/postbuild.mjs` が、実際のファイル名（ハッシュ付き）を書き込みます。
- HTMLは「ネット優先・つながらなければキャッシュ」、JS/CSS/画像は「キャッシュ優先」。
- キャッシュ照合には `ignoreVary: true` を必ず付けています。配信サーバーが `Vary` ヘッダ（例：`Vary: Origin`）を付けると、保存してあるのに一致せず圏外で真っ白になるためです（実際に `vite preview` で発生しました）。

## 3. 遊びながら気づいたことを残す（圏外OK）

プレイ画面の右上にある **📝** を押すと、その場でメモを残せます。圏外でも書けます。

- 「いまの場面」（どのステージの、どの工程か）が自動で付きます
- `操作しにくい / 分かりにくい / 長い / 短い / 音 / 見た目 / バグ / その他` から複数選べます
- ひとことの自由入力（任意・500文字まで）

電波のある所に戻ったら、タイトル画面 →「プレイ記録（テスト協力者向け）」→ **「まとめをコピーする」**。
クリア時間・メモ・アンケートが短いテキストになるので、そのままチャットに貼り付けて修正を頼めます。

```
# レトロ修復工房 プレイ記録のまとめ

## クリア記録
- radio / 73秒 / 2026-11-17T...

## 気づきメモ
- 古いラジオ / ホコリを拭き取る：[操作しにくい・短い] ダイヤルの穴がもう少し大きいと置きやすい

## アンケート
- radio：面白さ5/5・もう一度はい・別の品物はい
```

> **スマホだけでコードを直すことはできません。** 直すのはPCのある所（または電波のある所から私に頼む）になります。
> このメモ機能は「圏外で気づいたことを取りこぼさない」ためのものです。

## 4. 遊び方

1. タイトル → 「はじめる」
2. 修復する品物を選ぶ（3つともいつでも選べます）
3. 工程を上から順にこなす
   - **汚れ落とし**：品物の上を指でなぞる
   - **サビ磨き / レンズ磨き**：光っている輪の上で指を**往復**させる
   - **部品の取り付け**：画面下のトレイから、点線の位置までドラッグ
   - **最終動作**：光っているボタン（電源／ぜんまい／シャッター）をタップ
4. 修復完了 → 図鑑に登録 → 次の品物へ

PCではマウスで同じ操作ができます。

### 収録ステージ

| # | 品物 | 工程 |
|---|---|---|
| 1 | 古いラジオ | ホコリを拭く → サビを磨く → ダイヤルとつまみを付ける → 電源を入れる（ランプ点灯） |
| 2 | アンティーク時計 | ガラスの汚れを落とす → 歯車3つをはめる → 針2本を付ける → ぜんまいを巻く（動き出す） |
| 3 | レトロカメラ | ボディの汚れを落とす → レンズを磨く → 部品3つを付ける → シャッターを押す（撮影演出） |

## 5. 技術構成

| 項目 | 内容 |
|---|---|
| 言語 | TypeScript |
| ビルド | Vite 5 |
| 描画 | HTML Canvas 2D（**画像素材なし**。すべてコードで描画） |
| UI | 素のDOM + CSS（フレームワークなし） |
| 音 | WebAudio API で**合成**（音源ファイルなし） |
| 保存 | localStorage |
| 圏外対応 | Service Worker（自前・ライブラリなし） |
| テスト | Vitest |
| 実行時の依存パッケージ | **0個**（devDependencies のみ） |

バックエンド・データベース・アカウント登録・有料APIは一切使っていません。

### フォルダ構成

```
index.html
public/
  manifest.webmanifest  ホーム画面に置くための情報
  sw.js                 圏外対応（原本。ビルド時に dist へコピー＆書き換え）
  icon-180.png          iOS 用アイコン（ゲームのラジオの絵から作成）
  icon-512.png          Android 用アイコン
scripts/
  postbuild.mjs         ビルド後に sw.js へキャッシュ対象を書き込む
src/
  main.ts            起動
  app.ts             画面の切り替え、共通ボタン
  style.css          全画面の見た目
  core/
    viewport.ts      論理座標 <-> 画面座標の変換（タッチずれ防止）
    storage.ts       進行状況・設定の保存
    analytics.ts     プレイ記録・気づきメモ・アンケートの保存とJSON出力
    audio.ts         効果音の合成
    particles.ts     完成演出の粒
    offline.ts       Service Worker の登録
  game/
    tasks.ts         修復4種（なぞる/往復/ドラッグ/タップ）の中核ロジック
    session.ts       工程の進行役
    art.ts           汚れ・サビ・くもり・目印の共通描画
    stage.ts         ステージの型と画面の配置
    stages/          radio.ts / clock.ts / camera.ts
  screens/
    title / stageSelect / play / complete / collection / survey / note / data / thumb
tests/               自動テスト
```

### 設計で効いているところ

- **修復の仕組みをデータ駆動にした**：`ScrubMask`（なぞる）/ `PolishTask`（往復）/ `FitTask`（ドラッグ）/ `FinalTask`（タップ）の4部品を、ステージごとに並べ替えるだけで新しい品物が作れます。ステージ2・3はステージ1の仕組みをそのまま再利用しています。
- **中核ロジックをCanvas・DOMから切り離した**：だから自動テストで「最後までクリアできるか」を機械的に確認できます。
- **座標変換を1か所に集めた**（`core/viewport.ts`）：論理座標360×560を画面にcontain合わせするので、端末の画面サイズが変わってもタッチ位置と絵がずれません。
- **図鑑の絵とゲーム本編の絵が同じ関数**：見た目が食い違いません。アプリのアイコンも同じ絵から作りました。

## 6. 市場検証の機能

### 記録するイベント

| イベント名 | いつ |
|---|---|
| `game_start` | ゲームを開いたとき（1回の読み込みにつき1回） |
| `stage_start` | ステージを開始したとき |
| `stage_complete` | ステージをクリアしたとき |
| `stage_retry` | クリア済みのステージを選び直したとき |
| `next_stage_start` | 完了画面の「次の品物へ」から始めたとき |
| `session_end` | ページが隠れた／閉じられたのを**実際に検出できたときだけ** |

記録する項目：イベント名 / 発生時刻(ISO8601) / ステージID / ステージ開始からの経過時間(ms) / 匿名のローカル識別子 / セッションID。

**集めていないもの**：個人情報、位置情報、連絡先、広告ID、IPアドレス、端末情報。

### 記録の取り出し方（テスト協力者向け）

タイトル画面 →「プレイ記録（テスト協力者向け）」から:

- **まとめをコピーする** … クリア時間・メモ・アンケートを短いテキストにしてクリップボードへ（スマホ向け）
- **記録をJSONで保存する** … `retro-restoration-log-YYYYMMDD-HHMM.json` をダウンロード（全データ）
- **この端末の記録を消す** … 2回タップで消去

### アンケート

修復完了後に、4問の任意アンケートを表示します（面白さ5段階 / もう一度遊びたいか / 別の品物も修復したいか / 改善点の自由入力）。
**初クリアのときだけ自動で開き**、2回目以降は完了画面のボタンから任意で開けます。いつでもスキップできます。

### この方式の限界（重要）

- 記録は**その端末のブラウザのlocalStorageにだけ**残ります。サーバーがないので、**全ユーザーのデータを自動で集計することはできません**。協力者から個別にJSONファイル（またはコピーしたテキスト）を送ってもらう必要があります。
- ブラウザのシークレットモード、別ブラウザ、キャッシュ削除をすると記録は消え、匿名IDも作り直されます。
- `session_end` は `pagehide` / `visibilitychange` で検出しますが、アプリの強制終了や電源断では**検出できません**。検出できなかったぶんを推測で補うことはしていないので、`session_end` の件数は実際のプレイ終了回数より少なくなります。

## 8. 未解決の問題・未確認の項目

### 未確認（やっていないこと）

- **実機のスマートフォンでの確認をしていません。** iOS Safari / Android Chrome での実際のタッチ操作、音の鳴り方、画面サイズの収まりは未確認です。確認はPCのChromium（タッチ相当のPointerEventを合成）で行いました。
- **実際のホスティングへのデプロイをしていません。** 圏外対応の確認は `vite preview`（localhost）で行いました。HTTPSの本番URLでの動作、**ホーム画面への追加とアイコンの見え方は未確認**です。
- **効果音を耳で聞いての確認をしていません。** 合成の仕組みとON/OFFの切り替え（保存を含む）は動作しますが、音色の良し悪しは未評価です。
- iOSのSafariは、画面を触るまで音が鳴りません（仕様に合わせて初回操作までAudioContextを作らない作りにしています）が、実機での挙動は未確認です。
- 「まとめをコピーする」は、クリップボードが使えない環境では文章を画面に出して手動コピーしてもらう作りにしています。この**手動コピー側の経路は実機で未確認**です。
- 省電力モード・低スペック端末でのフレームレートは未測定です。

### 分かっている弱いところ

- 1ステージが**1分前後で終わってしまう可能性**があります（自動操作では38秒〜1分17秒でした）。人の指ではもう少しかかるはずですが、短すぎると感じたら `doneThreshold`（汚れの完了判定）や `strokeFactor`（磨きに必要な距離）で調整できます。
- 部品の取り付けで、**どの部品がどこに入るかは「いちばん近い点線」頼み**です。わざと遠くに落とせば失敗しますが、点線が2つ近くにあると取り違えても吸い付くことがあります。
- 図鑑の「修復前」の絵が暗く、品物が何なのか分かりにくい場合があります。
- 一度だけ、効果音のON/OFFが操作していないのに切り替わった記録が残りましたが、その後の通しプレイでは再現しませんでした（原因未特定）。
- アンケートはQ1〜Q3をすべて選ばないと「送信する」が押せません（Q4は任意）。部分回答は保存されません。
- iOSのホーム画面に追加したPWAは、OSが領域を空けるために保存データを消すことがあります（長期間使わない場合など）。大事な記録は早めに書き出してください。

## 9. 仕様があいまいだった点と、ここで決めたこと

| 迷った点 | 決めたこと | 理由 |
|---|---|---|
| プロジェクトの置き場所 | 既存リポジトリ `C:\DevFolder\my-claude-config` の**外側**の `C:\DevFolder\retro-restoration-game` に新規作成 | 「既存リポジトリの外側に独立して作成」という指示に合わせたため |
| ステージの開放条件 | **最初から3つとも遊べる** | 「次のアイテムも修復したい」を測るMVPなので、入口を狭めない |
| アンケートを出すタイミング | **初クリアのときだけ自動表示**。以降はボタンから任意 | 毎回出すと邪魔になり、再プレイの体験評価が下がるため |
| `session_end` の扱い | `pagehide` / `visibilitychange(hidden)` を**実際に検出できたときだけ**記録 | 推測で記録しない、という指示に従うため |
| 画像素材 | すべてCanvasのコードで描画（外部素材ゼロ）。アプリのアイコンも同じコードから書き出し | 著作権・ライセンスの問題を完全に避け、素材待ちで開発が止まらないようにするため |
| 効果音 | WebAudioで合成（音源ファイルゼロ） | 同上 |
| 画面の基準サイズ | 論理座標 360×560 を contain で合わせる | 端末差でタッチ位置と絵がずれないようにするため |
| 削除の確認 | ブラウザの `confirm()` を使わず、ボタンを2回押す方式 | モーダルダイアログを出さない方針のため |
| 圏外対応のやり方 | ライブラリを足さず、自前の Service Worker | 「不要な依存パッケージを追加しない」方針のため |
| 気づきメモ | ゲーム内に 📝 を置き、場面つきで保存 | 圏外ではコードを直せないので、気づきを取りこぼさない受け皿が要るため |

## 10. この先アプリとして出すときの拡張方針

今回のMVPには**実装していません**。公開を決めてから着手する想定です。

1. **まずWebのまま配布して検証する**：第2節のやり方でURLを作り、テスト協力者に渡す。記録を集めて「最後まで遊ばれたか」「次の品物に進んだか」を見る。
2. **数字がよければアプリ化**：今の構成はWebView前提なので、Capacitor（無料・OSS）で iOS / Android のガワをかぶせるのがいちばん手数が少ない。Canvasの描画ロジックはそのまま使えます。
3. **サーバーが要るのは集計を自動化するとき**：localStorageの限界（第6節）を外したくなったら、イベント送信先を1本足すだけで済むよう `core/analytics.ts` の `track()` に集約してあります。
4. **ステージを増やす**：`src/game/stages/` に1ファイル足して `stages/index.ts` に並べるだけです。工程の4部品は作り直す必要がありません。
5. **収益化を考えるとき**：ステージの追加パック（買い切り）が、このゲームの手触り（急かされない・邪魔されない）といちばん相性がよいはずです。広告の常時表示は、落ち着いた雰囲気を壊すので慎重に。
