# 道具の強化(続けたくなる仕組み) 設計

2026-11-18 / 佐俣さんと決定(短い設計)

## なぜ
品物をきれいにするだけで目的がなく、「1回閉じたら終わりそう」(佐俣さん)。
このMVPで測りたいのは「次も修復したいと思うか」なので、続ける理由を1つ足す。

## 決めたこと
- 3案(依頼人の物語 / 工房が育つ / 毎回ちがう壊れ方)から B「工房が育つ」を選び、その中でも **道具の強化だけ** を入れる(品物の仕入れ・工房の飾りは入れない)。
- 7品物は今まで通り **最初から全部遊べる**。

## 中身
- お礼: 初クリア 300円 / 再クリア 120円
- 道具3種 × 3段階(Lv1 は最初から持っている)

| 道具 | 効く操作 | 効き方 Lv1 / Lv2 / Lv3 |
|---|---|---|
| 布 cloth | 汚れ落とし(なぞる) | 拭く半径 ×1 / ×1.3 / ×1.6 |
| 磨き粉 polish | サビ磨き(往復) | 必要な距離 ×1 / ×0.75 / ×0.5 |
| ピンセット tweezers | 部品の取り付け | 吸い付く範囲 +0 / +12 / +24 |

- 値段: Lv2 = 250円、Lv3 = 600円(全部で 2,550円。7品物の初クリア合計 2,100円より少し多い)
- 道具屋の画面を新設。タイトル画面・完了画面から入れる
- 完了画面: 「お礼 +300円」と、次に買える道具までの残り(例「あと180円で大きい布」)
- プレイ中: 道具レベルを操作の数値に反映(拭き跡の大きさも変わる)
- 保存: 所持金と道具レベルを localStorage(既存の保存と同じ仕組み・壊れたデータからは初期値に戻す)
- プレイ記録: `tool_buy`(道具ID・レベル・値段)を追加。どの道具から買われるかを見るため(私の判断)

## 入れないもの
広告・ガチャ・ログインボーナス・時間制限・品物の解放・工房の飾り・課金

## 作り方
道具が効く所はすでに数値になっている(play.ts の brushRadius、PolishTask の strokeFactor、FitTask の snapRadius)。
ステージ定義は変えず、プレイ開始時に道具レベルから倍率を決めて、工程に渡す/上書きする。

## 作る人に任せること
- 道具屋の画面の見た目(既存の画面と同じ部品・色で)
- 道具の絵(Canvas か CSS で自作)
- 数字は定数1か所にまとめ、あとで調整しやすくする
